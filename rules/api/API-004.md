# API-004 — Canonical contract

0.2.0에 도입되었습니다. HTTP는 OpenAPI, protobuf RPC는 `.proto`, JSON WebSocket messages는 JSON Schema 또는 AsyncAPI 같은 형식을 선택할 수 있습니다. 도구 이름을 공통 의무로 고정하지 않습니다. code-first라면 선언된 코드 위치가 정본이고 생성된 schema가 투영이며, contract-first라면 schema가 정본입니다.

SSE는 HTTP response 안에서 `text/event-stream` framing을 사용하는 streaming contract입니다. 계약은 handshake와 event framing을 구분하고 `event`, `data`, `id`, `retry`, data payload, 순서, 정상 완료, 재연결·resume, stream 시작 전·후 오류를 다룹니다. OpenAPI 3.2의 sequential media type과 `itemSchema`처럼 기계 판독 가능한 표현을 사용할 수 있습니다. 선택한 OpenAPI 또는 framework toolchain이 이를 보존하지 못하면 JSON Schema·AsyncAPI 등 별도 schema를 연결하거나 provider-consumer 실행 계약을 exception evidence로 기록하고 재검토 trigger를 둡니다. “현재 생성기가 표현하지 못한다”를 protocol 자체가 schema를 가질 수 없다는 뜻으로 확대하지 않습니다.

Scalar 같은 renderer는 승인된 OpenAPI를 보여주는 소비자입니다. 실행 중인 endpoint와 계약의 일치는 별도 테스트로 확인합니다.

자료: [OpenAPI 3.2 sequential media types와 SSE](https://spec.openapis.org/oas/v3.2.0.html#sequential-media-types), [WHATWG server-sent events](https://html.spec.whatwg.org/multipage/server-sent-events.html).
