# MSG-002 — Message behavior

0.2.0에 도입되었습니다. 안내 여부·표시 위치·대상·말투·언어는 프로젝트가 정하지만, 정의된 조건은 구현자가 임의로 생략하지 않습니다. 성공·진행·업무 거절·장애·결과 미확인을 구분하고 비노출과 중복 억제, 동시에 여러 조건이 참일 때의 우선순위와 해제 조건을 명시합니다. 해당 없는 항목은 이유를 남깁니다.

## 표현과 작업의 경계

웹·앱의 번역은 해당 표현 계층이, 서버 발송 메일·알림은 서버 표현 계층이 관리하는 것이 기본입니다. 지원 언어가 하나라면 하나만 선언합니다. 없는 언어는 기본 언어로, 모르는 code는 일반 안내로 처리하고 원시 오류를 대신 보여주지 않습니다. 문장은 통째로 번역하며 parameter 이름과 타입, 날짜·숫자·복수형 포맷을 검사합니다. 웹·CLI·메일별 실제 표현 구현과 도구 선택은 프로젝트에 남깁니다.

사용자에게 보이는 설명과 내부 진단 정보는 [OBS-001](../observability/OBS-001.md), [OBS-002](../observability/OBS-002.md)에 따라 분리합니다. 공개 parameter는 허용 목록만 전달합니다. 내부 로그도 비밀정보 저장소가 아닙니다. 예상된 거절은 정책에 따라 기록을 생략하거나 낮은 수준으로 남기며 운영 알림을 자동으로 의미하지 않습니다.

재시도·보상·유실 불가 알림은 [ARCH-005](../architecture/ARCH-005.md)의 업무 흐름입니다. 번역 또는 로그 생성이 후속 작업의 트리거가 되지 않습니다. 모호성이 동작·권한·데이터·비용에 닿으면 [HITL-001](../hitl/HITL-001.md)에 따라 사람에게 확인합니다.

## 예와 검증

시간 초과에서는 「저장 결과를 확인하지 못했습니다」로 안내하고 실제 확인 전까지 재시도 안전을 가정하지 않습니다. 사용자 안내가 없는 내부 배치는 그 사실을 근거로 `not-applicable`이며 무관한 UI 테스트를 요구하지 않습니다. JSON Schema 통과는 필드 구조의 증거일 뿐 노출 동작·번역 품질의 증거가 아닙니다.

자료: [ICU message formatting](https://unicode-org.github.io/icu/userguide/format_parse/messages/). 특정 다국어 라이브러리를 의무화하지 않습니다. 자동 검증은 미구현이며 Phase 0 판정은 `human-review`입니다.
