# MSG-001 — Public outcomes

0.2.0에 도입되었습니다. 예상된 업무 거절·처리 중·성공과 내부 장애를 구분합니다. 공개 code는 의미를 식별하며 HTTP status를 대체하지 않습니다. HTTP에서 오류를 일괄 200으로 바꾸지 않고 해당 의미의 status를 유지합니다. UI가 소비하는 code와 parameter만 공유하고 백엔드 구현 패키지를 공유하도록 강제하지 않습니다.

## 정본과 호환성

프로젝트는 contract-first 또는 code-first 중 정본 방향을 하나 정합니다. contract-first는 계약에서 타입·문서 등을 만들고, code-first는 코드 정의에서 계약을 추출합니다. 생성물은 직접 수정하지 않습니다. 손으로 적는 수용 사례·번역은 각자 다른 책임의 정본이며 복제 스키마가 아닙니다. 도구 없이도 정본 파일과 실제 응답을 대조할 수 있으나 자동 검사로 주장하지 않습니다.

오류 code의 의미를 재사용하거나 parameter의 타입·공개 범위·필수 여부를 조용히 바꾸지 않습니다. [COMP-001](../compatibility/COMP-001.md)에 따라 공개 계약 변경을 검토합니다. 새 code 추가도 구버전 소비자의 모르는-code 처리 여부를 확인합니다. fallback은 안전한 일반 안내와 비자동 재시도를 기본으로 하며 정상 업무 결과인 척하지 않습니다.

## 예와 검증

`EXPORT_LIMIT_EXCEEDED`와 안전한 정수 `limit`을 반환하고 UI가 번역하는 예는 허용됩니다. DB exception 원문을 그대로 `message`에 넣거나 한국어 문장을 비교하는 것은 금지됩니다. 노출 결과가 전혀 없는 내부 작업이면 수신자와 경계를 확인하고 `not-applicable`입니다. HTTP가 아니면 transport mapping만 해당 없음으로 기록합니다.

형태 검사 외에 조건별 결과, 권한, 경계값, 구버전 응답 해석을 실제 실행으로 검사합니다. [TST-002](../testing/TST-002.md)의 사람 소유 수용 기준과 독립 검증을 유지합니다. [메시지 문서](../../docs/user-messages-and-errors.md)가 증거의 구분을 설명합니다.

자료: [OpenAPI](https://www.openapis.org/what-is-openapi), [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html). RFC 형식을 모든 transport에 강제하지 않습니다. 자동 검증은 미구현이며 Phase 0 판정은 `human-review`입니다.
