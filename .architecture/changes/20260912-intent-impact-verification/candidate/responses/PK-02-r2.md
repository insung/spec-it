확인 시각: 2026-09-15 09:57:34 KST. `inputs/PK-02.md`의 세 독립 사례와 결함 기록을 수동으로 검토했습니다. 각 프로젝트의 manifest/lock, 실제 코드·원본 문서·외부 실행 시스템은 제공되지 않았습니다. 따라서 정책 평가는 **shadow assessment**이며 아래 판단은 제공된 사실에 대한 동작 완료 검토입니다. 후보 규칙을 채택된 의무로 간주하거나 실제 정책 validator 통과로 보고하지 않습니다.

## 상위 변경 이슈에 남길 내용

기존 상위 변경 이슈에 각 결함의 **실패 → 결정/수정 → 새 QA run → 재확인**을 연결하면 됩니다. 별도 QA 폴더·저장소·시트나 새로운 추적 시스템을 만들 필요는 없습니다.

- Change/결함/Scenario·Case ID와 revision, 승인 원본 revision 및 위치.
- 원래 실패의 재현 조건·기대/실제·증거. 성공 run으로 덮어쓰지 않기.
- 확정 원인 또는 여전히 조사 중인 항목, 고친 문서·계약·코드·데이터·환경의 위치와 revision/build.
- 후속 run ID, 대상 build와 QA 기준, 환경·fixture, 실제 확인값, QA 확인자. 무관한 DB 항목은 사유 있는 N/A.
- 어떤 버전과 조건에서 정상인지, 실패·미확인 범위가 남아 있는지. 증거를 직접 연결할 수 있는 외부 위치가 있으면 원본 복사 대신 참조 가능.

수정과 QA가 끝나기 전에는 위 내용을 완료 사실처럼 미리 채우지 않습니다. 반복 사고가 다른 프로젝트에서도 발생했다는 자료가 없으므로 이번 결함만으로 공통 정책 개정이나 전 프로젝트 의무 검사를 요구할 근거는 없습니다. 우선 각 프로젝트의 해당 변경 기록에서 수정과 재발 방지 사례를 남기면 됩니다.
