# CHG-17 현재 상태와 QA 기록안

## 결론과 확인 범위

CHG-17/S-17의 현재 완료 여부는 `human-review`다. 보존된 기록에서는 **기획 rev3·디자인 rev8을 기준으로 실패한 run-1과, 수정 a2 이후 통과한 run-2**를 확인할 수 있다. 그러나 기획 rev4 승인 기록이 추가로 존재하므로 run-2의 통과를 변경된 요구의 통과로 사용할 수 없다. run-3은 링크 추가 알림만 있고 내용에 접근할 수 없어 최신 실행 결과도 미확인이다.

이 판단은 `inputs/PK-03.md`에 보존된 합성 snapshot을 읽은 수동 검토다. snapshot 확인 시각은 **2026-09-12T08:10:00Z**이며, 이것은 각 run의 실행 시각이나 이번 원본 재조회 시각이 아니다. plan/design 원본, 구현 코드, QA 코드, log-1/log-2 원문을 직접 열어 확인한 결과는 아니다. 아래 기록안은 기존 도구에 반영할 수 있는 제안이며 실제 CHG-17, qa-17, 저장소는 수정하지 않았다.

run-1은 run-2로 덮어쓰지 않는다. bug-17에는 “a2/run-2에서 기존 CASE-1 rev1의 관찰 불일치 해소”까지 기록할 수 있지만, 현재 이슈 종료 상태나 변경된 요구까지 해결됐다는 결론은 내릴 수 없다. 수정 코드에 접근하지 못했으므로 결함의 구체적인 원인도 확정하지 않는다.

## 다음 사례와 검증 범위

1. **CASE-1 rev2 초안 — 계정 공통 적용:** 출처를 rev4 export/decision-44로 명시한다. 동일 계정의 c1·c2에 a9 제외가 공통 적용되는지 관찰하고, 다른 계정은 영향받지 않는지 관련 경계를 확인한다. 기존 c1·c2가 동일 계정인지 주어진 fixture 정보로는 알 수 없으므로 계정 관계를 먼저 확인한다. 설정이 적용되는 시점과 다른 계정의 기대는 현재 자료가 충분하지 않으면 결정 항목으로 남긴다. 기존 rev1 기대값과 run 이력은 보존하고 새 revision 및 새 run을 연결한다.
2. **저장 실패 화면 사례 초안:** 저장 실패를 일으켰을 때 기존 값과 재시도 버튼이 보이는지 확인하는 사례를 plan rev3/design rev8 근거로 준비한다. rev4의 관련 문구와 rev9 승인 여부를 확인한 뒤 현재 수용 기준을 확정한다. 현재 자료에는 이 화면을 실행·관찰한 증거가 없으며, CASE-1의 선택 결과 통과가 화면 검증을 대신하지 않는다.
3. **고객 목적과 탐색:** run-2는 단순 저장 성공을 넘어 c1의 실제 미선택까지 기록했다는 점에서 제한적인 목적 관련 근거다. 계정 공통 요구의 실제 제외 성공과 전체 고객 목적 달성은 아직 검증되지 않았다. 계정 경계나 실패 후 재시도 등의 탐색 결과도 제공되지 않았다. 추가 탐색 가설을 승인된 새 요구나 확정 결함으로 취급하지 않는다.

새 run은 확정된 case revision, 구현·QA commit, 환경·DB/fixture, 예상과 실제, 증거·확인자, 결함·수정 연결을 고정해 남긴다. 이 문서는 사례와 실행 계획을 제안한 것이며 테스트를 실행하지 않았다.

## 기존 도구를 유지하는 인계안

상위 CHG-17을 조회 출발점으로 유지한다. 기획과 디자인은 기존 정본 도구에, 구현은 repo-A에, QA 사례·suite·실행 이력은 repo-B/qa-17에 둔다. dev-17, fix-17, qa-17의 CHG-17/S-17 참조를 이용하면 되고 QA 코드를 구현 저장소로 옮기거나 새로운 QA 폴더를 만들 필요가 없다.

CHG-17 요약에는 승인된 출처와 관측된 새 revision을 구별하고, 당시 대상과 현재 대상을 구별해 표시한다. 링크·ID 자체는 자동 수집·동기화·통합 화면이 아니다. 현재 설치된 서비스가 없으므로 담당자가 원본을 재조회한 시각과 확인 범위를 갱신해야 한다.

| 다음 확인 | 담당 제안 | 갱신 조건·완료 근거 |
| --- | --- | --- |
| 기획 기준 연결 정정 및 원본 최신성 확인 | owner product-1, 원본 접근 가능 담당자 | decision-44와 rev4 export를 CHG-17의 승인 근거에 연결. 접근 복구 후 실제 plan revision·이후 승인 여부 확인 |
| 오류 화면 기준 정리 | product-1과 디자인 담당자 | rev9 승인 기록 확보 또는 기준 동작 결정. 이후 관련 case revision 반영 |
| run-3와 현재 검증 대상 조회 | QA 담당자 qa-1 또는 qa-17 관리 담당자 | run-3 내용·출처/case/suite·구현 대상·환경·결과·증거 확인. 접근 전에는 미확인 유지 |
| 변경된 요구의 후속 실행 | 개발·QA 담당자 | 승인 기준과 실제 대상 확정 후 새 case/run 실행. 결과와 확인자 연결 |

담당 제안은 실제 배정이나 메시지 발송을 뜻하지 않는다. 출처 승인 변경, 구현·QA revision 변경, 환경·DB/fixture 변경, run-3 접근 복구가 재검토 조건이다.

CASE-1 rev1(plan rev3/design rev8)은 repo-A a1에서 실패했고(run-1, log-1, bug-17), fix-17/a2 후 repo-B b1·suite rev1·synthetic-stage-1·db-f1 조건에서 예상 결과와 일치했다(run-2, log-2, qa-1). 이는 기존 캠페인별 요구의 과거 통과다. decision-44에는 기획 rev4의 계정 공통 적용 승인이 보존되어 있어 새 case revision과 후속 검증이 필요하다. design rev9의 제품 승인, 저장 실패 화면 실행 결과, run-3 내용, 현재 원본·구현·QA·환경 상태는 미확인이다. CHG-17 전체 완료나 최신 QA 통과로 판정하지 않는다.

## 실제 읽은 출처와 정책 판단의 한계

- 과제 사실: `inputs/PK-03.md` 전체. locator들은 합성 식별자로만 사용했으며 네트워크 조회를 하지 않았다.
- 후보 지침: `source/AGENTS.md`, `source/skills/spec-it-check/SKILL.md` 전체.
- 관련 설명·선택 템플릿: `source/docs/traceability.md`, `source/docs/intent-and-verification.md`, `source/templates/testing/acceptance-case.md`, `source/templates/testing/verification-run.md` 전체. 출처·사례·실행 분리, 과거 결과 보존, 분산 도구 유지와 최신성 한계를 기록안에 반영했다.
- 실제 읽은 규칙: `source/rules/testing/TST-002.md`(사람 소유 수용 기준에 대한 독립 관찰), `source/rules/testing/TST-001.md`, `source/rules/testing/TST-006.md`, `source/rules/governance/GOV-003.md` 전체. 뒤의 세 규칙은 관련 경계를 확인하기 위해 읽었으며, 이 자료만으로 TDD·환경 안전·예외 위반을 판정하지 않았다.

CHG-17 프로젝트의 pinned 정책 버전·manifest·lock·exceptions는 입력에 없다. 따라서 이 검토는 후보 지침을 참고한 **shadow assessment와 QA 인계 제안**이며 정식 정책 준수/위반 판정이 아니다. 공식 enum으로 표현한 전체 검토 상태는 `human-review`이고, 표의 `failed`/`passed`는 원래 QA 실행 결과를 보존한 값이다. 실행형 checker를 돌리지 않았으므로 자동 검사 통과나 실제 종료 코드는 없다. 원본에 접근하지 못했으므로 원문 전체 대비 누락 없는 완전성 검증도 완료했다고 주장하지 않는다.
