확인했습니다. intent-owner의 이번 답변을 기준으로, 제외 목록은 **계정 공통 설정**이며 해당 계정의 A·B 캠페인에 모두 적용하는 것으로 정리합니다. 앞서 제안한 캠페인별 저장 방식과 미확인 분석 초안은 이 결정으로 대체합니다. 코드는 수정하지 않았습니다.

제가 이해한 결과는 다음과 같습니다.

- 계정 운영자가 제외 목록을 편집합니다. 같은 계정의 모든 A·B 캠페인이 그 계정의 저장된 목록을 사용합니다.
- 저장 전 편집값은 결과에 영향을 주지 않습니다. 저장에 성공한 뒤 시작하는 선택부터 새 목록을 적용합니다.
- 저장 성공 전에 시작한 선택에는 새 목록을 소급 적용하지 않습니다. 이미 시작한 송출도 그대로 유지합니다.
- 제외하지 않은 항목에는 기존 선택 조건을 그대로 적용합니다. 제외를 해제한 항목도 기존 조건을 만족할 때만 후보가 됩니다.
- 다른 계정의 설정과 결과에는 영향을 주지 않습니다.
- 별도 예외가 없으므로, 제외 후 남는 후보가 없더라도 제외 항목을 다시 넣지 않습니다. 이때 선택 결과에는 항목이 남지 않는 것으로 이해했습니다. 화면이나 송출 계층에서 빈 결과를 어떻게 표현하는지는 현재 제공 코드로 확인할 수 없습니다.

검증할 사례는 아래와 같습니다. 모두 검증 계획이며, 아직 실행한 결과는 아닙니다.

| 사례 | 기대 결과 |
| --- | --- |
| 계정 X에서 항목 p를 제외하고 저장 성공 후 A·B 캠페인이 선택 시작 | 두 경로 모두 p를 결과에 포함하지 않음 |
| 같은 계정에 여러 캠페인·asset이 있음 | 어느 캠페인·asset에서도 동일한 계정 공통 제외 목록을 적용 |
| p를 편집 중에만 제외하고 저장하지 않음 | 마지막으로 저장에 성공한 목록을 계속 적용 |
| 편집한 목록의 저장이 실패함 | 편집값은 적용되지 않고 이전 저장 목록을 유지 |
| 선택이 시작된 뒤 새 목록 저장에 성공함 | 이미 시작한 선택에 새 목록을 소급 적용하지 않고, 이후 시작한 선택부터 적용 |
| 송출 중인 항목을 새로 제외하고 저장함 | 진행 중인 송출은 유지하고 이후 시작하는 선택에서는 제외 |
| 제외하지 않은 항목이 기존 선택 조건을 만족하거나 만족하지 않음 | 만족하는 항목은 기존 규칙대로 처리하고, 만족하지 않는 항목은 계속 탈락 |
| 제외 목록에서 p를 제거하고 저장함 | 이후 선택에서 p가 기존 조건을 만족하면 다시 후보가 될 수 있음. 무조건 선택되지는 않음 |
| 기존 조건을 만족하는 후보가 모두 제외됨 | 결과에 제외 항목을 되살리지 않으며 선택할 항목이 없음 |
| 제외 목록이 비어 있음 | 기존 선택 동작과 같은 결과를 냄 |
| 계정 X와 Y에 같은 항목 식별자가 있고 X에서만 제외함 | X의 결과에서만 제외되며 Y의 설정·선택·송출은 영향을 받지 않음 |

구현 관점에서 q1의 `settings[campaignId]`는 계정 공통이라는 확정 의도와 맞지 않습니다. 이후 구현을 준비할 때는 계정 식별 경로, 저장 성공의 경계, 선택 시작 시 사용하는 설정, A·B의 공통 처리 위치를 확인해야 합니다. `activeItems` 내부와 실제 저장 계층이 제공되지 않았으므로 필터 위치나 저장 방식은 아직 단정하지 않겠습니다. 이는 사용자가 다시 답할 제품 질문이 아니라 코드에서 조사할 사항입니다.

기존 캠페인별 설정 데이터의 존재 여부도 현재 자료로는 알 수 없습니다. 실제 데이터가 있고 계정별 설정으로 옮기는 과정에서 서로 다른 목록의 충돌이 발견된다면, 임의로 합치거나 버리지 않고 그 구체적인 경우를 별도 결정으로 제시하겠습니다. 이번 확인을 데이터 삭제나 변경 실행의 승인으로 확대하지 않습니다.

앞서 나눈 주요 제품 결정 5개는 모두 확인됐고, 현재 제공된 범위에서 미결정은 0개입니다. 이번 질문은 없으며 추가 제품 질문 예상은 0회입니다. 사용자·적용 범위·경로·시점·예외 정책을 모두 답해 주셔서 앞선 2~3회 예상이 줄었습니다. 결정 근거는 이번 intent-owner의 명시적 답변입니다. 기획 내용은 이 답변으로 확정할 수 있지만, 프로필 선택과 구현 적합성을 검증했다는 의미는 아닙니다.

오타 수정 ‘제외목룍’ → ‘제외목록’의 승인도 유지합니다. 의미·동작·저장 형식이 바뀌지 않는 문구 수정으로 분리해 처리할 수 있으며, 추가 승인은 필요하지 않습니다. 다만 이번 요청은 이해한 결과와 검증 사례를 설명하고 구현은 하지 않는 것이므로, 오타를 포함한 실제 파일 수정은 하지 않았습니다.
