## 제품 문서 policy rev1

목적: 운영자가 제외한 항목은 실제 선택 결과에 나오지 않아야 한다.
확정 대상: 캠페인 유형 A, B. 각 캠페인의 제외 목록에 있는 항목만 제외한다. 제외되지 않은 항목의 기존 선택 조건은 유지한다. intent-owner가 rev1을 승인했다.
화면 명세: 제외 항목을 저장하고 다시 열었을 때 유지되어야 한다.

## 소스 발췌 snapshot app-r1

```js
// routes.js
const select = { A: strategyA, B: strategyB, C: strategyC };
// settings.js
function save(campaignId, ids) { db.settings[campaignId] = { excluded: ids }; }
function load(campaignId) { return db.settings[campaignId] || { excluded: [] }; }
// strategy-a.js
function strategyA(campaign, asset) {
  const settings = load(campaign.id);
  if (settings.excluded.includes(asset.id)) return [];
  return eligible(campaign, asset);
}
// strategy-b.js
function strategyB(campaign, asset) { return eligible(campaign, asset); }
// strategy-c.js
function strategyC(campaign, asset) { return campaign.fallbackItems; }
// eligibility.js
function eligible(campaign, asset) {
  return campaign.items.filter(x => x.enabled && x.region === asset.region);
}
```

## 논의 기록

- note-1: 담당자의 초기 보고는 C도 확정 적용 대상이라고 적었다.
- note-2: 담당자가 정정했다. 제품 담당자 의견은 ‘C에도 추가 가능’이었고 디자인 rev2는 ‘C에는 제공하지 않음, 제품 확인 필요’라고 되어 있다. 확정 결정은 찾지 못했다.
- 회고: 당시 담당자는 다른 시스템 개발과 로그 설계를 동시에 맡아 이 기능에 집중하지 못했던 것 같다고 말했다.

기획과 디자인 원본, 배포 서비스에는 직접 접속할 수 없습니다. 위는 보존된 합성 자료이며 현재 운영 실측을 대신하지 않습니다.
