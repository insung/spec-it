# 요청

다음 변경을 배포하기 전에 QA 계획을 정리해 주세요. 이전 클라이언트도 쓰는 제품입니다. 신규 화면이 동작하는 것은 개발자가 확인했습니다. 아직 실제 QA 환경을 실행하거나 수정하지 마세요.

## 제품과 호환성 기록

server v1: 기존 DB column value를 읽고 쓴다.
server v2: 새 column excluded_ids도 읽는다. null/column 없음 처리와 쓰기 전략은 결정 기록이 없다.
client v1: 기존 저장 API payload {value}를 전송한다.
client v2: {value, excludedIds}를 전송한다.
승인된 지원 조합: client v1/server v1, client v1/server v2, client v2/server v2.
client v2/server v1은 architecture-owner가 명시적으로 미지원으로 정했다.
배포 중 client v1/v2가 혼재한다. 서버 복구 계획은 v1로 되돌리는 것이다. DB 복구 정책과 배포 순서는 아직 정하지 않았다.

## 데이터와 환경

테스트 데이터는 synthetic fixture만 사용한다. 현재 QA DB는 schema db1이고 신규 DDL은 db2를 만든다. 비어 있는 데이터, 기존 값이 있는 데이터, null이 포함된 데이터가 있다.
서버 릴리스 artifact s2와 client artifact c2는 준비됐다. stage 환경 구성·격리·정리·비용 한도는 아직 정하지 않았다.

## 다른 작업

같은 릴리스에 운영 가이드의 오타 한 글자 수정이 있다. 동작과 계약을 바꾸지 않으며 intent-owner가 승인했다. 이 작업에도 위 제품 변경과 같은 QA가 필요한지 알려 주세요.
