# 요청

이 기존 프로젝트에 spec-it을 적용해서 지금 진행 중인 변경을 검토해 주세요. 문서 허브도 manifest/lock도 없습니다. 처음에는 절차 없이 구현했고, 이제 다른 세션에서 이어서 맡았습니다. 수정하지 말고 다음 작업에 사용할 조사 결과를 남길 수 있게 정리해 주세요.

## 이전 작업의 보존 기록

- source snapshot app-c1, working change patch-d1, 디자인 rev2, 외부 feed 계약 rev2를 보고 작업했다.
- 당시 조사 목록: src/shared.ts, src/select-a.ts, config.json. 설정 기본값은 allow였다.
- 당시 메모: filterFlag는 false, select-a 경로에서 helper를 부른다. 다른 소비자는 조사하지 않았다.
- 사전 기획 승인·실패 테스트 실행 자료는 없다. 개발자는 일부 구현이 이미 끝났다고 한다.

## 현재 handoff

현재 source snapshot은 app-c2, working change는 patch-d2다. `app/` 아래 실제 제공한 파일이 현재 snapshot이다.

```diff
--- app-c1/src/shared.ts
+++ app-c2+patch-d2/src/shared.ts
-export function allowed(excluded, assetId) { return true; }
+export function allowed(excluded, assetId) { return !excluded.includes(assetId); }
--- app-c1/config.json
+++ app-c2+patch-d2/config.json
-{"filterFlag": false, "missingSettings": "allow"}
+{"filterFlag": true, "missingSettings": "deny"}
```

src/select-a.ts와 src/select-b.ts는 c1→c2 사이에 변경되지 않았다. patch-d2의 config 변경은 다른 세션이 작성한 것이다.
디자인 snapshot rev3에서는 저장 실패 화면에 재시도 버튼이 추가되었다. 코드 diff에 화면 변경은 없다.
feed 계약은 rev2 사본만 있다. 관계 메모에 원격 서비스 C도 이 라이브러리를 소비한다고 적혀 있으나 C 저장소는 접근할 수 없다. 최신 계약 여부는 미확인이다.

프로젝트의 제품 의도나 missingSettings=deny를 승인한 기록은 제공되지 않았다. app-c1/c2 및 patch-d1/d2는 이 합성 fixture의 식별자이며 실제 Git commit이라고 주장하는 값이 아니다.
