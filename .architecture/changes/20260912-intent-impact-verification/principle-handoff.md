# 원칙 문서 후속 인계 — 프로젝트 선택 양식

이 기록은 같은 원고를 수정할 권한이나 모든 프로젝트의 공통 의무가 아니다. 현재 원고에는 쓰지 않는다. 별도 집필과 분석은 독립 진행할 수 있고, 동일 원고를 편집하기 직전 최신 revision/dirty 상태와 겹치는 작성 범위를 확인한다.

| 항목 | 현재 인계 내용 |
| --- | --- |
| 문제 | 기획을 읽어도 별도 경로가 누락되거나 같은 해석의 테스트로 정당화될 수 있음 |
| 관찰 | 합성 기준선 24개 중 22 met/2 unmet. 실제 앱 운영 검증이 아님. [원본과 판정](baseline/results.md) |
| 가설 | 의도 되읽기와 지속 가능한 영향/검증 인계가 이해 격차를 줄일 수 있음. 합성 후보에서는 누락 두 사례가 회복됐지만 실환경 효과는 아직 미검증 |
| 결정 | 기존 권한/독립 검증 규칙을 재사용하고 인계 공백을 우선 보완. QA 도구 이관과 전체 lifecycle 강제는 제외 |
| 반례·한계 | 기존 0.4.0도 명시적 검토 요청에서는 핵심 행동을 충족. 후보 24/24는 한 합성 run이며 새 규칙 필요성이나 일반 모델 성공률을 입증하지 않음. 일반 자동 활성화·실환경·원문 전체 감사는 미실행 |
| 정책 ID | 기존 GOV-001/002, HITL-002, TST-002/003/006; GOV-005/TST-007은 제안 이력이며 채택하지 않음 |
| 증거 상태 | baseline 22/24와 candidate 24/24의 원본·판정, 네 독립 감사와 세 finding의 수정·재검증 기록이 존재. 로컬 0.5.0 릴리스 준비 완료, 발행은 pending |
| 공개 범위 | 합성 예제와 일반 절차만 공개. 회사/사람/비공개 사고 원문·링크·배포 식별자는 원고에 복사하지 않음. 추가 공개는 출처별 권한 확인 필요 |
| 원고 접근 | 현재 최신 원고 미조회. 병행 세션 완료 여부를 추정하지 않음 |
| 편집 전 확인 조건 | 집필 담당과 대상·범위를 조율하고 최신 원고/진행 중 변경을 읽은 후 겹치는 부분만 재검토. 해당 권한이 없으면 인계만 수행 |
| 인계 수신·재개 | intent-owner가 실제 집필 담당에게 전달할 때 최신 후보 증거와 원고 상태를 확인. 현재 전달 완료로 기록하지 않음 |

파일럿 가설을 검증된 원칙으로 승격하지 않는다. 실제 제품 파일럿과 실패·반례가 확보되면 출처와 공개 경계를 유지한 채 원칙을 다시 판단한다.
