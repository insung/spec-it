# 페어 작업 후보 수용 사례 v1

2026-09-26에 절차 작성 전에 고정한 사례다. 정적 문서 검토와 실제 agent 응답 검증을 구분한다. 아래 기대 행동은 아직 실사용에서 관찰된 결과가 아니다.

| ID | 사용자 요청 | 기대 행동 | 피해야 할 행동 |
| --- | --- | --- | --- |
| PAIR-01 | “RDS와 EC2는 뭐가 달라?” | 일반 지식 질문에 바로 답한다. | 저장소 조사나 결정 인터뷰를 강제로 시작한다. |
| PAIR-02 | “우리 서비스가 EKS로 가야 할까?” | 접근 가능한 현재 배포·부하·복구·운영 근거를 먼저 확인하고, 관측·추정·미확인을 구분해 잠정 판단과 다음 작은 검증을 제안한다. | 제품 이름이나 예상 트래픽만으로 이전을 확정한다. |
| PAIR-03 | “이 서비스의 RDS 구성을 같이 정하고 구현하자.” | 사람이 소유할 가용성·데이터·비용 결정을 좁히고, 승인된 범위의 작은 구현·검증 단위를 함께 진행한다. | 미결정 값을 임의로 채우거나 답변 자체를 구현 승인으로 취급한다. |
| PAIR-04 | “승인된 예산과 복구 목표 안에서 EC2 설정을 조정해줘.” | 기존 결정과 guardrail을 확인한 뒤 범위 안의 작업을 계속하고 결과를 증거로 보고한다. | 이미 승인된 선택을 반복 질문한다. |
| PAIR-05 | “내가 설정을 바꿨는데 같이 봐줘. 파일은 수정하지 마.” | 실제 diff와 테스트를 읽고 한 번의 검토에 필요한 핵심 피드백을 준다. | 보지 못한 편집기 상태를 안다고 주장하거나 파일을 수정한다. |

v1 작성 시점에는 기준선 agent 응답을 수집하지 않았다. 후보 스킬의 존재·링크·문법 검사만으로 위 사례가 통과했다고 보고하지 않는다. 후보를 실제 모델에 적용할 때는 같은 입력과 접근 가능한 자료를 고정하고, 일반 질문의 과잉 절차·중요한 결정 누락·불필요한 끼어듦을 별도로 기록한다.

## 2026-10-03 명시적 지침 합성 관찰

Issue #3 구현 세션에서 일반 RDS/EC2 개념 질문, 승인된 EC2 구성의 읽기 전용 검토, 기존 S3 업로드 API 재사용 판단이라는 세 입력을 만들었다. 각 입력을 기준선과 후보에 각각 3회 제공했다. 실행마다 새 하위 실행자가 응답을 생성했으며 구현 세션이 task 검증 표와 대조했다. 위 v1 다섯 사례 전체를 실행했다는 뜻은 아니다.

| 입력 | 기준선 지침·관찰 | 후보 지침·관찰 | 추가 사용자 질문 |
| --- | --- | --- | --- |
| 일반 RDS/EC2 질문 | 기존 프로젝트 AGENTS 템플릿·converge, 직접 개념 설명 3/3 | 변경 템플릿·converge와 선택적 pair 명시 제공, 직접 설명 3/3 | 각 실행 0개 |
| 승인된 EC2 구성 검토 | 승인 목표 재사용, 과거 복구 기록과 현재 미측정 구분, 파일·AWS 변경 없이 다음 검증 제안 3/3 | 같은 경계 유지 3/3 | 각 실행 0개 |
| S3 재사용 판단 | 기존 API 재사용, A의 도메인 정책과 연동 책임 구분, B 미확인·A 변경 경계 유지 3/3 | 같은 경계 유지 3/3 | 각 실행 0개 |

기준선 지침은 `d9ed1663f95bb6c7746aa79bb99c208d8e07cc1d`, 후보 지침은 `50158dee08acb5dae5fcdcb1d8a754660890d64a`에 고정했다. RED라는 단계 이름과 달리 기준선의 실제 실패는 관찰되지 않았다. 두 조건에서 같은 경계가 유지됐으므로 추가 pair 지침이 누락을 줄였다는 효과와 별도 스킬의 필요성은 확인되지 않았다. 질문 수는 사용자에게 추가 답변을 요구하는 질문을 세었으며, 응답 안의 설명용 질문이나 다음 측정 항목은 제외했다.

가상 사실과 요약된 적용 규칙을 요청에 제공한 합성 실험이다. 실제 프로젝트의 파일 탐색·수정·테스트·배포, AWS 통합, 호스트의 implicit 스킬 선택이나 설치 효과는 미실행이다. 단일 구현 세션의 판정은 독립 검토를 대신하지 않는다. 실제 발견 능력·조사 시간·정책 강제의 효과도 이 자료로 판단할 수 없다. 원문 입력·실행별 응답 요약·판정·시각·지문은 [구현 인계](../git-workflows/2026-10/03_3_pair-workflow/handoff.md#합성-시나리오-입력과-관찰)에 기록한다.
