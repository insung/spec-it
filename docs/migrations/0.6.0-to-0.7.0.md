# 0.6.0 → 0.7.0 migration guide

상태: **공개 릴리스**. 공개 권위는 annotated tag `v0.7.0`이며 기존 프로젝트를 자동 업그레이드하거나 active policy loop를 자동 활성화하지 않는다.

## 변경 범위

- 규칙·profile의 규범 의미는 `0.6.0`에서 바뀌지 않는다.
- Python 표준 라이브러리 기반 vendor-neutral runner와 Claude Code adapter를 추가한다.
- Light/Hard 분류, 고정 tag의 rule 원문 조회, fingerprint dedup과 redacted ephemeral metric을 제공한다.
- manifest/lock version, policy digest, manifest digest, pinned tag와 selected rule source의 내부 무결성을 확인한다.
- 일반 finding은 advisory다. `policy-unavailable` 또는 확정된 material open decision 뒤 mutation만 좁게 deny한다.
- 범용 validator, deterministic lock generator, Codex adapter, CI gate와 command hook fail-close는 추가하지 않는다.

## 기존 프로젝트의 재수렴

기존 프로젝트는 `0.6.0`에 계속 고정할 수 있다. `0.7.0`을 선택할 때 다음 순서로 별도 재수렴한다.

1. manifest, lock, exception과 실제 선택 profile을 읽는다.
2. 정확한 annotated tag `v0.7.0`에서 policy digest를 계산하고 manifest와 lock을 같은 version으로 재생성한다. lock을 손으로 부분 수정하지 않는다.
3. 프로젝트가 Claude Code를 사용하며 local checkpoint가 필요한지 별도로 결정한다. policy pin과 실행 활성화는 같은 결정이 아니다.
4. 활성화를 선택한 경우 [설정 예제](../../examples/claude-hook-pilot/settings.local.json)를 프로젝트의 `.claude/settings.local.json`에 맞게 복사하고 절대 policy 경로를 지정한다. local 설정이 source control에 포함되지 않는지 확인한다.
5. `SessionStart`, material prompt, read-only tool, mutation tool, invalid lock과 `Stop`을 프로젝트의 비파괴 fixture에서 확인한다.
6. missing executable, runner error와 timeout은 command hook에서 fail-open일 수 있음을 운영자에게 알리고, hard gate가 필요하면 별도 wrapper/SDK 결정을 한다.

## Rollback

실행 장치만 되돌리려면 project-local Claude hook 항목을 제거한다. 이는 policy version을 낮추지 않으며 project source를 수정하지 않는다. 정책 pin 자체를 `0.6.0`으로 되돌리려면 그 tag에서 manifest/lock을 다시 수렴하고 `0.7.0`에만 의존하는 project-local 절차가 없는지 먼저 확인한다.

## 남은 구현

실제 authenticated model behavior, 모든 Claude lifecycle의 end-to-end 수용, Codex adapter, 범용 validator·lock generator, CI enforcement와 package/plugin 배포는 이번 릴리스의 완료 증거가 아니다.
