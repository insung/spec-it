# 0.4.0 → 0.5.0 migration guide

상태: **발행됨**. 공개 권위는 annotated tag `v0.5.0`이다. 이 문서나 새 tag가 기존 프로젝트 또는 설치된 스킬을 자동 갱신하지는 않는다.

## 변경 범위

- 새 read-only `spec-it-impact`와 기존 specify/clarify/converge/check/evolve의 의도·신선도·검증 인계 안내.
- 선택적 영향/사례/run template와 출처·경로·실행 기록 설명. 구현 저장소에 QA 코드·폴더를 강제하지 않는다.
- 규칙 ID, risk profile, 공개 schema와 기존 DB 전달 책임은 이번 후보에서 변경하지 않는다. 계획했던 GOV-005/TST-007 추가는 채택하지 않는다.

기존 프로젝트는 0.4.0에 계속 고정할 수 있다. 후보를 평가할 때 정책 digest만으로 스킬 동일성을 증명하지 말고 실제 사용하는 스킬·템플릿까지 포함한 source revision/snapshot을 기록한다. `v0.5.0` 발행 후 업그레이드를 선택하면 실제 released source, manifest와 lock을 정상 수렴 절차로 다시 대조한다. 수렴은 별도 QA 도구 설치 권한이 아니다.

## 알려진 0.4.0 lock 불일치

v0.4.0 commit `6a4ea01eb09bfb116ff24fd2d5253889086f9a77`의 같은 정책 파일 102개를 계산하면 다음과 같다. 두 계산은 각 상대 path + NUL + file bytes + NUL을 SHA-256에 넣는다.

| 순서 | SHA-256 |
| --- | --- |
| 전체 상대 POSIX 경로를 한 번에 정렬 | 3360e1545cf9fe85469f484e3cbd2ba1ebc2ffbdfe4ded2f72255a5bc4c3a5b1 |
| VERSION → rules → profiles → schemas, 각 그룹 내부 정렬 | 2e54ebfe90ee889af1cc581ee209936b387ee5f913f9504a3ac83611f69b6b4f |

기존 self lock은 두 번째 값을 기록했으나 [TOOL-002](../../rules/tooling/TOOL-002.md)는 전체 경로 정렬 계약이다. 계산 메커니즘은 재현했지만 당시 실행 명령 원본을 확보한 것은 아니다. 기존 tag/lock을 덮어써 이력을 지우지 않는다. 0.4.0 검토 시 실제 revision과 관측 digest를 함께 남기고 무결성 일치를 주장하지 않는다.

`0.5.0` 후보는 VERSION/rules/profiles/schemas를 고정한 뒤 전체 상대 POSIX 경로를 한 번에 정렬해 다시 계산하고 self lock과 대조했다. 정확한 값과 실행 경계는 [0.5.0 release checklist](../releases/0.5.0-checklist.md)에 기록한다. 입력 bytes가 바뀌면 재계산하며, 위 `0.4.0` digest를 미래 후보에 복사하지 않는다. 기존 프로젝트도 source·manifest bytes에서 재수렴하므로 hardcoded digest 교체로 끝내지 않는다.

## 채택 절차와 남은 구현

후보 행동 재실행, 독립 의미 검토, 최종 source/lock 대조와 `HEAD == origin/main == v0.5.0^{}` 확인을 릴리스 절차에서 수행했다. connector·watcher·QA runner·CI enforcement는 추가하지 않았다. 합성 행동 검증과 구조 검사를 실제 제품 QA 또는 자동 스킬 활성화로 보고하지 않는다.

기존 설치 스킬 다섯 개가 이 저장소를 가리키는 live symlink인 환경에서는 설치 명령을 실행하지 않았어도 미발행 worktree 변경이 보일 수 있다. 새 `spec-it-impact`는 전역 설치하지 않았다. immutable release 사용자는 발행 tag를 확인한 뒤 별도 설치·고정 절차를 따라야 한다.
