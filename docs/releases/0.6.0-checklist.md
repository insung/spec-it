# 0.6.0 release checklist

이 문서는 정책 저장소 자체의 `0.6.0` 릴리스와 공개 경계를 검증하는 증분 증거입니다. 개별 프로젝트의 준수나 자동 validator의 성공을 뜻하지 않습니다.

## Release identity

- Version: `0.6.0`
- Released on: `2026-09-22`
- Previous published version: `0.5.0`
- Release tag: annotated `v0.6.0`
- Current public authority: annotated `v0.6.0`
- Compatibility: 새 공통 code 의무를 추가하는 pre-1.0 minor; 기존 프로젝트는 자동 업그레이드하지 않음
- Policy digest: `sha256:e5eb3ef0d2efacb6387e918c716a375e26103fea6b9347d5e2e8ef26a4661885`
- Self manifest digest: `sha256:8002d5807a1ce7d1399fbfce31b1d427d7a9ef4064a2e9db831556d1a3d56b94`

정책 digest는 repository-relative POSIX path 전체를 한 번 정렬한 `VERSION`, `rules/`, `profiles/`, `schemas/`의 path + NUL + bytes + NUL로 계산합니다. 문서와 스킬은 digest에 포함되지 않으므로 전체 재현에는 annotated release tag가 필요합니다.

## Local preparation verification

- [x] `CODE-005`와 `CODE-006`의 condition, evidence, exception, owner와 manual enforcement를 확인했다.
- [x] `backend-service`, `serverless-function`, `python` profile의 rule reference와 version을 확인했다.
- [x] 설정·주석·코드 convention 문서와 0.5.0 → 0.6.0 migration을 연결했다.
- [x] 단일 프로젝트의 환경변수 key 이름은 공통 core 밖에 두고 project lint 또는 private overlay가 소유하도록 경계를 유지했다.
- [x] VERSION, self manifest/lock, AGENTS, README, changelog와 migration 안내를 `0.6.0`으로 재수렴했다.
- [x] policy와 manifest digest를 최종 후보 bytes에서 계산해 lock과 대조했다.
- [x] YAML/JSON 구조, profile rule reference, 변경 문서 링크와 whitespace를 로컬에서 확인했다.

## Publication gates

- [x] 승인된 파일만 stage하고 release commit을 만든다.
- [x] 검증된 release commit에 annotated `v0.6.0` tag를 만든다.
- [ ] commit과 tag를 원격에 push한다.
- [ ] `HEAD == origin/main == v0.6.0^{}`와 annotated tag identity를 확인한다.

로컬 커밋과 tag는 원격 공개를 뜻하지 않습니다. 인증 복구 뒤 원격 identity를 별도로 확인합니다.

## Known limits

- 두 규칙은 한 프로젝트의 관측을 일반화한 manual human-review 의무이며 validator, Ruff rule 또는 CI action이 아닙니다.
- schema와 profile 구조 검사는 실제 애플리케이션에서 설정 계약이나 주석 freshness를 자동 판정하지 않습니다.
- Python 설정 key 상수화와 특정 settings framework는 공개 공통 정책에 포함하지 않습니다.
