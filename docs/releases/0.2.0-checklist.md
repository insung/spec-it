# 0.2.0 release checklist

이 문서는 정책 저장소 자체의 0.2.0 구조와 릴리스 경계를 검증하는 증분 증거입니다. 개별 프로젝트가 0.2.0을 준수한다는 증거가 아니며, 실행 validator·CI·runtime enforcement가 구현됐다는 뜻도 아닙니다.

## Release identity

- Version: `0.2.0`
- Date: `2026-09-08`
- Previous version: `0.1.0`
- Release tag: `v0.2.0`
- Compatibility: new obligations require explicit project reconvergence; no automatic upgrade

`schema_version: 0.1.0`은 정책 버전이 아니라 artifact 형식 버전입니다. 0.2.0에서 기존 형식을 깨지 않았으므로 schema version은 올리지 않습니다. 개별 profile도 내용이 바뀌지 않았다면 자체 version 0.1.0을 유지할 수 있습니다.

## Verification

- [x] 모든 0.2.0 rule과 profile이 `active`이고 draft release 표기가 없다.
- [x] 모든 rule front matter와 profile YAML이 schema와 구조 계약을 만족한다.
- [x] infrastructure trait profile은 완전한 evaluation block을 가진다.
- [x] profile이 참조하는 rule ID가 존재하고 중복 rule ID가 없다.
- [x] manifest, unit manifest, lock, exception, check report, message contract와 관련 template·fixture가 schema를 만족한다.
- [x] Markdown 내부 링크가 유효하고 공개 core에 개인·회사 고유 정보가 없다.
- [x] 다섯 instruction-only skill의 구조와 참조가 유효하다.
- [x] `VERSION`, README, CHANGELOG, self manifest·lock과 project template이 0.2.0 릴리스 상태에 맞는다.
- [x] 0.1.0→0.2.0 migration이 자동 업그레이드 금지와 재수렴 절차를 설명한다.
- [x] clean release commit에 annotated `v0.2.0` tag가 연결된다.

## Known limits

- 실행 가능한 schema validator, lock generator와 `spec-it:check` CLI는 Phase 1 대상입니다.
- `enforcement.implementation: planned`인 규칙은 `pass`가 아니라 project별 `human-review`입니다.
- frontend, embedded와 product-AI 상세 profile은 실제 pilot trigger까지 보류합니다.
