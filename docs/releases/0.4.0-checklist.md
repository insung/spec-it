# 0.4.0 release checklist

이 문서는 정책 저장소 자체의 0.4.0 초안 구조와 릴리스 경계를 검증합니다. 아직 공개 release evidence가 아니며 개별 프로젝트 준수나 실행 validator의 구현 증거도 아닙니다.

## Release identity

- Version: `0.4.0`
- Date: not-released
- Previous version: `0.3.0`
- Release tag: not-created
- Compatibility: new lock and conditional profile obligations require explicit project reconvergence; no automatic upgrade

lock `schema_version: 0.2.0`은 정책 버전이 아닙니다. 새 `policy_digest` 필수 필드 때문에 lock artifact 형식만 올립니다. manifest와 profile schema version은 0.1.0을 유지합니다.

## Verification

- [x] lock은 released source의 version과 content digest를 고정하고 draft worktree의 version label만으로 생성하지 않는다.
- [x] `DATA-009`는 object decision owner, definition authority와 executor를 구분하고 중앙 SQL 저장소를 모든 객체의 업무 소유자로 간주하지 않는다.
- [x] 승인된 DB release definition과 그 digest를 참조하는 environment history를 구분하며, 환경 기록 추가가 release identity를 바꾸지 않는다.
- [x] baseline과 current-state definition projection은 선택 사항이고, 사용할 때 authority와 release chain 대조를 요구한다.
- [x] historical·emergency reconciliation은 보존하되 정상 pre-apply gate의 증거로 주장하지 않는다.
- [x] 특정 migration 제품, 파일 이름 규칙, 저장소 topology와 UI를 공통 의무로 고정하지 않는다.
- [x] HTTP streaming은 wire contract와 stream open 전 HTTP status·open 후 typed event 오류를 구분한다.
- [x] generic SSE fixture는 schema를 만족하며 runtime conformance를 주장하지 않는다.
- [x] `runtime/aws-ec2`와 `deployment/docker-compose`가 독립 축이고 Compose만으로 host redundancy를 주장하지 않는다.
- [x] `runtime/aws-ec2`는 interruptible capacity, capacity shortage와 replacement recovery를 평가하되 Spot 비율이나 minimum capacity 숫자를 공통값으로 고정하지 않는다.
- [x] `DATA-010`은 engine 공통 casing을 강제하지 않고, `capability/rds`는 새 project-owned table·column에 `lower-snake-case` 기본값을 제공하며 legacy·외부 소유 이름은 보존한다.
- [x] `capability/rds`는 infrastructure evaluation 구조로 topology, capacity, failover, recovery, maintenance, heavy DDL와 ownership boundary를 평가한다.
- [x] infrastructure threshold와 topology 선택은 project manifest와 ADR 소유로 남는다.
- [x] repository-scoped skill discovery와 `.gitignore` merge 절차가 기존 사용자 파일을 보존한다.
- [x] schema, profile rule reference, Markdown link, version, manifest·policy digest가 일치한다.
- [x] 공개 core에 private project 식별자, 별도 lifecycle 정책 또는 project-specific 사례가 없다.

## Known limits

- deterministic lock generator, policy bundle assembler, validator/CLI와 CI enforcement는 구현하지 않았습니다.
- DB release manifest·environment history schema, migration runner, DB lock integration과 definition reconciliation은 구현하지 않았습니다.
- SSE framing, proxy buffering, disconnect·reconnect·resume, typed event와 consumer UI 동작의 runtime 검사는 구현하지 않았습니다.
- EC2 provisioning, Spot interruption handler, replacement capacity coordinator, Compose deploy coordinator, health traffic integration, rollback executor와 topology verification은 구현하지 않았습니다.
- RDS provisioning, failover·PITR·restore executor, heavy-DDL guard와 runtime capacity verification은 구현하지 않았습니다.
- 별도 lifecycle 정책과 project-specific 사례는 0.4.0 공통 범위에 포함하지 않으며 별도 명세·결정이 필요합니다.
- 이 checklist의 release identity는 tag 생성과 공개 검증 전까지 초안입니다.
