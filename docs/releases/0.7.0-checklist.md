# 0.7.0 release checklist

이 문서는 정책 저장소 자체의 `0.7.0` 릴리스와 실행 장치의 경계를 검증하는 증분 증거입니다. 개별 프로젝트의 규칙 준수, 모든 Claude 환경의 lifecycle 성공 또는 fail-close enforcement를 뜻하지 않습니다.

## Release identity

- Version: `0.7.0`
- Released on: `2026-09-22`
- Previous version: `0.6.0`
- Release tag: annotated `v0.7.0`
- Compatibility: local opt-in 실행 표면을 추가하는 pre-1.0 minor; 기존 프로젝트는 자동 업그레이드하거나 자동 활성화하지 않음
- Policy digest: `sha256:1f55ee3d47398333eaad2b3dcf2af84ca42deb7e8f876f16d154dc39df2de9b0`
- Self manifest digest: `sha256:1f3466f3d972f0851a3bfe6452a5a7606cf460ae6efd87758e21c0f5be1614eb`

정책 digest는 repository-relative POSIX path 전체를 한 번 정렬한 `VERSION`, `rules/`, `profiles/`, `schemas/`의 path + NUL + bytes + NUL로 계산합니다. 실행 코드와 문서는 digest에 포함되지 않으므로 전체 재현에는 annotated release tag가 필요합니다.

## Implementation and review evidence

- [x] vendor-neutral core와 Claude adapter가 분리되어 있다.
- [x] local opt-in이 없으면 source와 state를 바꾸지 않는 no-op이다.
- [x] manifest/lock version, generated marker, policy digest, manifest digest, pinned tag와 selected rule source를 확인한다.
- [x] Light/Hard 선택, rule budget, fingerprint dedup, redacted ephemeral metric과 좁은 mutation deny를 contract test로 확인했다.
- [x] Claude 설정 예제를 shell interpolation 없는 command/args exec form으로 수정했다.
- [x] Stop은 system message만 반환하며 자동 continuation을 만들지 않는다.
- [x] Python unit/contract test 22개가 통과했다.
- [x] JSON fixture/settings parsing, YAML 구조, profile rule reference, 변경 문서 링크와 whitespace를 확인했다.
- [x] Claude 공식 hooks/settings 문서를 2026-09-22 다시 확인하고 SessionStart·PreToolUse·Stop 및 command hook fail-open 경계를 대조했다.
- [x] 고위험 Python HTTP API의 격리 worktree 약식 파일럿에서 9개 분류 scenario, 기존 application test 164개와 Ruff 기준선을 확인했다.

## Publication gates

- [x] `0.6.0` 정책 변경과 active policy loop 구현을 분리된 commit/branch로 보존한 뒤 순서대로 병합했다.
- [x] VERSION, self manifest/lock, AGENTS, README, changelog, migration과 roadmap을 `0.7.0`으로 재수렴했다.
- [x] policy와 manifest digest를 최종 후보 bytes에서 계산해 lock과 대조했다.
- [x] 승인된 파일만 stage하고 release commit을 만든다.
- [x] 검증된 release commit에 annotated `v0.7.0` tag를 만든다.
- [ ] commit과 tag를 원격에 push한다.
- [ ] `HEAD == origin/main == v0.7.0^{}`와 annotated tag identity를 확인한다.

로컬 커밋과 tag는 원격 공개를 뜻하지 않습니다. 인증 복구 뒤 원격 identity를 별도로 확인합니다.

## Known limits

- 실제 Claude prompt hook 연결은 확인했지만 authenticated model behavior, model 비용과 모든 lifecycle event의 end-to-end 수용은 미검증입니다.
- command hook 실행 파일 누락, 일반 오류와 timeout은 fail-open일 수 있습니다. 별도 wrapper/SDK가 없는 hard enforcement가 아닙니다.
- 최초 파일럿의 9개 분류 scenario와 164 application tests/Ruff는 제한된 초기 관측이며 제품 성공·사용자 수용·일반 성공률이 아닙니다.
- active policy loop는 Claude-first local opt-in입니다. Codex adapter, shared team setting, 범용 validator·lock generator, CI/release gate와 package/plugin 배포는 구현하지 않았습니다.
- 규칙의 기존 `planned` enforcement는 그대로이며 hook context가 개별 프로젝트의 실제 준수를 증명하지 않습니다.
