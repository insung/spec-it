# Issue #3 검토 기준

구현 전에 고정한 pr-review 입력이다. 구현 세션은 이 파일과 검증 입력을 읽지 않는다.

## 사용 방법

1. handoff와 task의 실제 처리·검증 근거를 AC와 대조한다.
2. 아래 기계 확인은 직접 실행하고 판단 질문은 실제 문서를 읽어 확인한다.
3. TC-R01은 [고정 경계 입력](review-input-reuse-boundaries.md)의 입력 절과 대상 지침만 새 실행자에게 제공한다. 3회 결과를 판정 주체가 기대와 대조한다.
4. 원본 보존·검증 범위·변경 경로를 확인하고 검토 대상 HEAD와 문서 증거 커밋을 구분한다.

## AC별 기준

| AC | 기계 확인 (리포 루트) | 판단 질문 | 실패로 보는 예 |
| --- | --- | --- | --- |
| AC-01 | README·pair·S3·템플릿의 AGENTS/후보 상태 검색 | 기본 경로와 선택적 지침, 실제 실행 주체의 구분 여부 | 스킬 설치나 상시 관찰·자동 선택을 존재만으로 단정 |
| AC-02 | 지침의 승인·미확인 안내 검색 | 승인된 범위와 새 중요한 결정 구분 여부 | 반복 승인 강제 또는 외부 수정 권한 추정 |
| AC-03 | S3 독립 문서의 여섯 단계·Mermaid 코드 블록 확인 | 입력부터 실제 import·버전·계약 검증까지 이어지는지 | 개념 설명만 있고 실제 재사용 확인 누락 |
| AC-04 | ARCH-001/002/003과 domain-core-libraries 대조 | 소비자 요구와 별도 릴리스 비용·어댑터 경계 구분 여부 | B의 계획을 사용 사실로 간주, 두 소비자면 무조건 별도 저장소 |
| AC-05 | 후보 front matter·합성 입력·실행 횟수·결과 근거 확인 | 합성 결과를 호스트 자동 선택·실사용 효과로 확대하는지 | baseline 통과를 실패로 이름 붙이거나 후보 필요성 입증 단정 |
| AC-06 | 변경 문서의 상대 링크 검사, git diff --check | 실제 기준선과 설명 상태 일치 여부 | 존재하지 않는 local-verification.md를 현재 제공 기능으로 링크 |
| AC-07 | git diff --name-only d9ed166..HEAD, 원본 snapshot digest 확인 | 보호 경로·기존 작업·이력 보존 여부 | 정책·실행 코드·다른 Issue 작업 반입 |
| AC-08 | 계획/task/handoff 경로와 review 브랜치 분리 확인 | 실제 검증·인계·승인 경계 기록 여부 | 구현 세션이 검토 입력을 열람하거나 미실행을 완료로 기록 |

## 우회 확인

| 확인 | 방법 |
| --- | --- |
| 완료 근거 | task의 완료 행과 처리 내용의 실제 diff·커밋 대조 |
| 실행 대상 | handoff의 소스 commit·dirty 식별·명령·출력과 현재 PR HEAD 비교 |
| 자기 검증만 존재 | 고정 경계 입력 3회 재실행과 구현 합성 결과 구분 |
| scope 과장 | 후보 효과·실사용·자동 선택·B 검증·runner 가용성 단정 검색 |

## 공통 확인

| 확인 | 기준 |
| --- | --- |
| 정본 | 규칙 의미의 새 복제나 규칙 파일 변경 없음 |
| 커밋 | 계획·구현·기록의 주제 분리와 기존 index·원본 보존 |
| 기록 | 실제 실행·미실행·한계·남은 승인 표기, 계획 이탈의 행 추가 |
| 전달 | 원격에 없는 문서를 확인된 링크처럼 게시하지 않는 상태 |
